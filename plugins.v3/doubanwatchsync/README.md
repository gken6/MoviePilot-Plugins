# 豆瓣观看同步 2.0.3（MoviePilot V3）

由 gken6 维护。基于豆瓣观看同步 1.2.1 改造，来源归属见仓库 NOTICE.md。MoviePilot 已连接媒体服务器的选择、用户名筛选、Webhook、轮询及观看状态判定沿用原逻辑。

## 安装

适用于 MoviePilot V3。在插件页面的插件仓库管理中添加 `https://github.com/gken6/MoviePilot-Plugins`，刷新插件市场，搜索“豆瓣观看同步”并安装。也可将此地址追加到 `PLUGIN_MARKET`（保留已有地址，以英文逗号分隔）。

## 直连 Emby

配置页下半部分独立管理直连 Emby，不需要添加到 MoviePilot 的媒体服务器中。填写服务器名、地址、用户名、密码后点击 ＋，后台自动登录获取 Token 和用户 ID，并统计当前账号可见的影片和剧集数量。列表显示“正在获取token”“获取失败”“正常”“未启用”四种状态，支持多个服务器、编辑、删除和启停。编辑密码留空保留原值；删除服务器保留历史观看记录。停用或删除后，该服务器的自动轮询和历史记录自动重试/重扫停止。

账号数据存放在本插件的数据命名空间，管理 API 不返回密码、Token 或用户 ID。直连账号不写入 MP 的媒体服务器配置或 MP 用户名筛选框。旧版直连配置首次加载时迁移，之后以新列表为准。媒体数量读取失败显示 —，不伪装成 0；正常账号定时刷新数量。

## 修正匹配

“已同步”“待同步”记录均可点击“修正 / 重新同步”，填写豆瓣条目页面中的数字编号。该记录之后优先使用手动编号；先验证并同步新条目，再尝试撤销旧条目的错误标记。部分失败会保留明确的待处理提示及重试按钮，不会显示完全成功。另一个历史记录仍使用旧编号时，保留其豆瓣标记。

修正窗口可明确选择提交状态：影片仅为“看过”，剧集为“在看 / 看过”。沿用记录中的有效状态，旧版电影的无效“在看”默认改选“看过”。提交失败不会更改历史档案或撤销旧标记。待同步记录保存当时实际判定的状态，不再在未匹配时一律保存为“在看”。

仅在豆瓣返回整数 `r=0` 时确认成功；布尔值 `false`、异常响应和网络错误均保留失败提示，不输出完整响应或 Cookie。没有进行额外的远端状态回读验证。

原错误标记的撤销端点必须能从豆瓣官方页面脚本核实，否则停止撤销并显示“旧标记待撤销”。该流程已有模拟测试，尚未以实际豆瓣 Cookie 验证或执行真实写入。

无条目内容可移入“无条目”，停止自动匹配和轮询触发同步，并从已同步统计中移除。以后可以指定新编号，或移回待同步恢复匹配。

## 仪表盘

仍使用原仪表盘数据及时间线布局，修正后显示新条目标题和封面。“无条目”不计入已同步统计；修正任务未完成时保留操作提示。修复内嵌海报缓存达到显示限制后，后续封面始终不加载的问题。

## 安装与回退

推荐通过插件市场安装与更新。手动安装时，将本仓库 `plugins.v3/doubanwatchsync/` 目录放入 MoviePilot 的本地插件目录，并同步本地插件清单。升级前备份本插件源码及配置数据，回退时仅恢复本插件所需数据，避免覆盖其他插件的后续更新。

## 验证

需要 pytest 和 beautifulsoup4。在仓库根目录执行：

```
python tests/v3/doubanwatchsync/run_isolated.py
node tests/v3/doubanwatchsync/frontend.mjs
```

隔离测试模拟宿主存储、Emby 和豆瓣边界，不访问实际媒体服务器或豆瓣，不修改真实观看记录。覆盖账号迁移与隔离、多服务器 CRUD、Token 状态、数量、凭据脱敏、启停、人工修正及部分失败重试、无条目恢复、并发保护和仪表盘统计。
