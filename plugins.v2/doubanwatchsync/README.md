# 豆瓣观看同步 2.3.11（MoviePilot V2）

由 gken6 维护。感谢 [honue](https://github.com/honue/MoviePilot-Plugins) 的“豆瓣书影音档案”插件。本插件中读取 MoviePilot 已配置媒体服务器的非直连功能，参考该插件改编；独立直连 Emby 的功能由 gken6 自主提出并设计，不依赖 MP 媒体服务器配置。来源与许可见 [NOTICE.md](NOTICE.md)。本次登录态调整保持 MP 媒体服务器的选择、用户名筛选、Webhook、轮询及观看状态判定逻辑。

## 安装

适用于 MoviePilot V2.15.6（安装范围 >=2.15.6,<3.0.0；较早 V2 版本尚未验证）。在插件页面的插件仓库管理中添加 `https://github.com/gken6/MoviePilot-Plugins`，刷新插件市场，搜索“豆瓣观看同步”并安装。也可将此地址追加到 `PLUGIN_MARKET`（保留已有地址，以英文逗号分隔）。

## Cookie 自动续登

实际同步需要操作豆瓣时，按以下顺序获取登录态：

1. Cookie 框填写了内容时，优先使用手填 Cookie；为空或明确失效时再回退。手填 Cookie 不覆盖插件自动保存的 Cookie。
2. 再尝试插件自身持久保存的 Cookie。
3. 前两级均为空或明确失效时，仅在开启“使用CookieCloud”的情况下读取并检查 CookieCloud Cookie；有效时保存到插件，后续复用。
4. 仍无有效 Cookie 时，开启“Cookie 过期自动重新登录”并填写豆瓣手机号/邮箱、密码后，使用 MoviePilot 内置无头浏览器进行账号登录。
5. 遇到滑块、安全验证或账号登录未成功时，发送豆瓣官方二维码；通过豆瓣 App 扫码并确认后，插件核验并保存 Cookie，继续当前同步。

两个开关可以同时开启：CookieCloud 控制云 Cookie 回退，自动续登控制账号和扫码登录。关闭自动续登仍可使用手填 Cookie、已保存 Cookie 和已启用的 CookieCloud。缺少账号密码不会阻止有效 Cookie 的同步。手填 Cookie 内容改变后重新核验，不复用之前的有效性缓存；清空后恢复插件保存 Cookie 的优先级。账号登录成功后同时保存浏览器 User-Agent。网络或临时风控异常不视为明确失效，不会据此连续切换账号或重复发送二维码。

不设置定期登录检查，也不在保存配置或打开页面时登录。只有实际观看同步、失败记录重试、重扫写入或人工修正需要操作豆瓣时才检查登录态；明确失效时续登后重试当前写入一次。自动登录成功本身不会把任何观看记录标为已同步，仍须豆瓣确认写入成功。

账号密码保存在 NAS 的 MP 插件配置中，Cookie 保存在插件持久数据空间；管理接口只返回登录状态及时间，不返回 Cookie 或密码。并发同步共用续登锁，账号密码改变或停用后的迟到结果不会覆盖现配置。网络异常或临时拦截不直接当成 Cookie 过期，观看记录继续保留等待重试。

## 账号登录失败时扫码登录

账号密码登录失败、需要滑块或无法确认登录成功时，切换到豆瓣官方二维码登录。通过 MP 已配置且允许“插件”消息的通知渠道提交二维码图片通知；同时在插件“豆瓣登录”设置中显示当前二维码。请打开豆瓣 App 扫码，并在手机上确认登录。二维码最多有效 6 分钟，豆瓣提前使其失效时立即结束等待，不自动刷新或重复发送。

插件保留这次浏览器会话，等待官方页面完成登录。确认电影站账号导航及 `dbcl2` / `ck` 后保存 Cookie，继续当前同步；只有实际豆瓣写入成功后才计入已同步与仪表盘。扫码失败、过期或网络错误保留待同步记录，登录失败冷却 30 分钟后在下次同步/失败重试时再尝试。密码模式遇到验证但扫码入口也不可用时安全停止。插件停用或账号密码变更会取消旧扫码会话。

“获取登录 Cookie”只在点击时执行一次上述顺序，重新检查本地和 CookieCloud 登录态，必要时进行账号/扫码登录；不写入任何观看记录，适合首次登录或二维码过期后重新获取。请先保存账号密码及启用设置。普通观看同步无需点击该按钮，会在检测到 Cookie 失效时自动进入同样的流程。保存配置、打开页面不会主动登录，没有定期登录检查。通知发送由 MP 控制，插件不另存通知凭据；企业微信自建应用直接发送二维码图片，可在微信中查看、保存或长按识别；不再发送图文链接。其他渠道继续使用 MP 的原生图片通知，文字渠道可进入插件设置扫码。

已移除 AI 验证开关、模型调用与滑块操作。二维码和当前会话只在有效期内提供，不持久保存二维码；插件重启后旧二维码不再显示。二维码来自豆瓣官方登录页。微信直接读取豆瓣登录页生成的二维码 PNG，校验后写入权限受限的临时文件，上传为图片素材并发送 `msgtype=image`，通知结束后删除临时文件。复用 MP 微信客户端的现有凭据、Token 和代理，以及 MP 通知路由、渠道启用状态和插件消息筛选，不修改宿主代码或其他通知。

## 神医助手 Cookie 同步

配置页提供独立的 Emby 地址、管理员用户名、密码输入框，默认关闭自动同步。填写安装了神医助手的 Emby 地址（如 `http://192.168.50.191:8096`），使用有管理员权限的账号，开启右上角自动同步开关并点击“保存连接设置”。不需要修改 MP 媒体服务器或直连观看服务器。密码留空保留原值；切换地址或账号后需要重新填写。

手填、插件保存、CookieCloud、账号或扫码取得的 Cookie 验证有效后，后台同步至神医助手的豆瓣 Cookie，同一 Cookie 成功后不重复发送。失败显示独立状态，后续观看触发可在五分钟冷却后重试，不阻止正常的豆瓣观看同步；没有额外的定期登录检查。

“立即同步 Cookie”同时保存当前连接输入并检查已有 Cookie，优先手填，再用插件保存值；不会额外触发账号或扫码登录。自动开关关闭时仍可手动同步。没有有效 Cookie 或网络状态无法确认时停止，不会清空神医助手原 Cookie。

适配神医助手新版 Emby 通用配置页，已在 Strm Assistant Pro 3.0.0.52 实机验证。保存前读取配置，仅替换 `MetadataRefreshOptions.DoubanCookie`，通过官方 UI 保存接口生效，再回读核对。配置结构不兼容时停止。管理员账号密码及插件自行获取的会话仅存于插件数据，管理 API 不返回密码、Token 或 Cookie，连接不跟随重定向。建议使用可信内网或 HTTPS 地址。

## 设置分组

“豆瓣登录”管理 Cookie、账号续登及扫码登录；“同步操作”用于执行一次失败重试或历史重扫；“仪表盘显示”控制月份、每月条目数量和封面，不影响同步规则。

## 直连 Emby

配置页下半部分独立管理直连 Emby，不需要添加到 MoviePilot 的媒体服务器中。填写服务器名、地址、用户名、密码后点击 ＋，后台自动登录获取 Token 和用户 ID，并统计当前账号可见的影片和剧集数量。列表显示“正在获取token”“获取失败”“正常”“未启用”四种状态，支持多个服务器、编辑、删除和启停。编辑密码留空保留原值；删除服务器保留历史观看记录。停用或删除后，该服务器的自动轮询和历史记录自动重试/重扫停止。

账号数据存放在本插件的数据命名空间，管理 API 不返回密码、Token 或用户 ID。直连账号不写入 MP 的媒体服务器配置或 MP 用户名筛选框。旧版直连配置首次加载时迁移，之后以新列表为准。媒体数量读取失败显示 —，不伪装成 0；正常账号定时刷新数量。

## 修正匹配

“已同步”“待同步”记录均可点击“修正 / 重新同步”，填写豆瓣条目页面中的数字编号。该记录之后优先使用手动编号；先验证并同步新条目，再尝试撤销旧条目的错误标记。部分失败会保留明确的待处理提示及重试按钮，不会显示完全成功。另一个历史记录仍使用旧编号时，保留其豆瓣标记。

修正窗口可明确选择提交状态：影片仅为“看过”，剧集为“在看 / 看过”。沿用记录中的有效状态，旧版电影的无效“在看”默认改选“看过”。提交失败不会更改历史档案或撤销旧标记。剧集重新同步时会核对各服务器合并后的整部作品进度，全部看完为“看过”，否则为“在看”；编号仍然保存并供后续集数复用。失败记录重试时重新读取播放进度。

仅在豆瓣返回整数 `r=0` 时确认成功；布尔值 `false`、异常响应和网络错误均保留失败提示，不输出完整响应或 Cookie。没有进行额外的远端状态回读验证。

原错误标记的撤销端点必须能从豆瓣官方页面脚本核实，否则停止撤销并显示“旧标记待撤销”。该流程已有模拟测试，尚未以实际豆瓣 Cookie 验证或执行真实写入。

无条目内容可移入“无条目”，停止自动匹配和轮询触发同步，并从已同步统计中移除。以后可以指定新编号，或移回待同步恢复匹配。

## 仪表盘

仍使用原仪表盘数据及时间线布局，修正后显示新条目标题和封面。“无条目”不计入已同步统计；修正任务未完成时保留操作提示。修复内嵌海报缓存达到显示限制后，后续封面始终不加载的问题。

## 安装与回退

推荐通过插件市场安装与更新。手动安装时，将本仓库 `plugins.v2/doubanwatchsync/` 目录放入 MoviePilot 的本地插件目录，并同步本地插件清单。升级前备份本插件源码及配置数据，回退时仅恢复本插件所需数据，避免覆盖其他插件的后续更新。

微信纯图片兼容层适配MoviePilot V2.15.6 企业微信自建应用接口。微信机器人模式或宿主接口不支持纯图片时显示通知失败，并保留设置中的二维码，不退回图文链接；首次导入插件不会连接微信。

## V2 兼容说明

复用 V2 的媒体服务器、CookieCloud、鉴权、通知类型及 Vue 联邦界面。账号登录使用宿主 BrowserSessionHelper 的浏览器上下文；二维码微信图片沿用 V2 原生管理员/用户收件人路由及渠道开关。延后任务在插件内按 ID 登记，替换及停用时取消尚未执行的任务。初次安装默认停用且不迁移已有“豆瓣书影音档案”数据，避免重复同步；配置后自行启用。

## 观看记录海报

观看记录通过 NAS 后端缓存展示豆瓣和 TMDB 海报，避免浏览器直接请求外部图片。已有缓存立即显示，缺失图片异步补齐，页面刷新不会等待下载。下载失败时显示标题占位，五分钟后再次打开或刷新记录可重试；不需要重新同步观看状态。图片请求不使用豆瓣 Cookie 或媒体服务器凭据。

## 剧集匹配与看完判定

- 同一服务器的上下集共用作品匹配。例如“无悔的选择（上集）/（下集）”的手动豆瓣编号只需填写一次；OAD #3、#4、#5 等不同作品保持隔离。
- 升级时合并旧的上下集记录和相同手动编号，并保存升级前的插件数据备份。编号冲突或尚有修正任务时不猜测合并；未成功的待同步记录继续保留。
- 普通剧季须核对豆瓣公开总集数及 Emby 每一集的已播放状态；特别篇按对应作品的上下集归组，不把整个 S00 或其他 OAD 计入。单集已播放、播放到末集、媒体库只有部分集数，都不能据此判定整部看完。
- 全部集数明确已播放才同步“看过”，否则保持“在看”。总集数或播放信息未知时不猜测看完。手动匹配、自动同步、失败重试、重扫使用同一规则。重扫遇到明确未完成的旧“看过”记录时可修正为“在看”；信息未知时保留旧状态。
- 有可确认的分集信息时，记录页显示“已看 X/Y 集”。

## 豆瓣总集数

所有剧集的总集数只采用豆瓣条目数据。人工填写编号时复用已读取的豆瓣集数；匿名刷新失败时保留上次成功取得的总数。读取失败且没有有效记录时显示“总集数待获取”，不使用媒体库集数或上下集数量替代，也不据此标为看过。Emby 仅提供对应分集及各集播放状态。

同一作品可跨不同 OAD 编号和副标题归组，例如 LOST GIRLS 的“再见，希娜之墙”上下集与“迷失在残酷的世界里”归为同一作品。

## 跨服务器观看

同一豆瓣编号、同一季的已匹配记录会读取各个启用服务器的实时分集播放状态，按集去重后合并。比如 A 看完 1～6 集、B 看完 7～12 集，豆瓣总数为 12 时可以判定看过；两边重复观看同一集只算一次。不同豆瓣编号、不同季、无条目、正在修正及停用/删除的直连服务器不参与合并。MP 媒体服务器配置和原来的用户筛选方式保持原样。

记录仍保留各自的服务器来源，显示“合并已看 X/Y 集”；成功提交后，同作品已同步记录显示一致的豆瓣状态。自动同步、手动匹配、失败重试和重扫使用同一套判定，并串行处理豆瓣提交，避免两台服务器互相覆盖状态。升级时只刷新本地进度，不批量修改豆瓣标记；下一次正常同步或手动重扫时应用新判定。

普通剧季按集号对应。S00 特别篇不能直接比较服务器本地的集号，只在分集 IMDb/Tvdb/Tmdb 标识或明确标题能够一对一对应时合并；无法确认对应关系或媒体服务器暂不可达时，不凭数量相加推断看完，也不据不完整信息撤回原有看过状态。豆瓣总集数未知时继续显示“总集数待获取”。

媒体库重建导致普通剧季的旧条目 ID 失效时，会重新定位剧集，并要求新条目刮削的豆瓣编号与已匹配编号一致后才读取进度；不会仅凭同名剧集参与合并。

## 按豆瓣识别影片和剧集

豆瓣条目类型优先于 TMDB/Emby 的媒体库分类。类型来自豆瓣明确的 API 字段、条目页面的影片/剧集信息，信息不足时只读官方标记表单确认；不根据所调用的接口、S00 位置或“没有集数”猜测类型。已确认的类型缓存在插件内；读取失败且没有可靠缓存时保留待处理提示，不提交未经确认的状态。

例如 Emby 把《进击的巨人 最终季 完结篇 前篇》放在 S00 中，豆瓣却是独立影片：手动同步按影片提交“看过”，不会因缺少剧集总数被改成“在看”。自动观看触发时沿用影片的观看完成条件，重试/重扫时核对对应单集；不要求整季或上下篇全部看完。前篇编号只绑定该服务器的当前集，后篇不会自动复用；豆瓣确认为剧集的同一季仍共用匹配和跨服务器分集进度。

识别为影片时，旧的剧集分组和进度会清除，本地记录显示为影片；重设匹配之前保存本插件记录备份。升级不自动重新提交旧的失败手动任务，点击“重试”或重新指定编号后才应用新类型规则。


## 按源媒体编号匹配（2.3.10）

手动填写的豆瓣编号始终优先。自动匹配先读取 Emby/Jellyfin 元数据中的 IMDb；IMDb 无结果时，再尝试将 TMDB 编号转换为 IMDb，使用豆瓣的 IMDb 映射接口查找同一作品。电影与电视剧的 TMDB 数字编号分属不同类型，转换时保留类型。两者均没有结果时，按名称/原名、年份和类型搜索，逐个核对候选；不会直接采用搜索首条。源元数据没有 IMDb/TMDB 时也可使用明确刮削的豆瓣编号。

普通剧集使用所属 Series 的编号，不能拿单集编号代表整部剧。名称兜底还需核对当前季号：第一季使用作品首播年；第二季及以后优先查询 TMDB 当前季的 air_date，再参考 Emby 当前季的独立首播年份。Emby 沿用第一季年份而又无法取得当前季日期时，提示“当前季年份未知”并保留待匹配，不用首季年份猜测，也不把第一季编号直接复用到第二季。两季确实同一年播出时，仍需明确匹配当前季号。

S00 特别篇使用当前集的 IMDb、具体名称和首播年份，不拿主剧编号或主剧名称套用全部特别篇；只剩 TMDB 单集编号而不能转换 IMDb 时，继续尝试本篇名称和年份。即使 Emby 存放在剧集目录，S00 的候选也可以是豆瓣独立影片或特别篇剧集，最终状态继续按豆瓣实际类型处理。普通季则严格要求剧集类型，电影严格要求影片类型。

候选必须同时满足完整名称/别名、年份、类型和适用的季号；发现明确的编号冲突、无法确认类型或出现多个符合条件的条目时保留待匹配，可手动填写豆瓣编号或选择“无条目”。成功映射缓存六小时，查询失败不会永久缓存成无条目。

失败队列每次重试均重新按当前规则核对，历史搜索留下的豆瓣编号不作为可信来源；重扫写入前也确认源元数据与原档案一致，不一致时保留原记录等待手动修正。升级不批量撤销或改写旧豆瓣标记；已同步错误条目可在观看记录中填写正确编号重新同步，沿用原有人工修正流程。
